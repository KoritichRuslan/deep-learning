# ЛР1. Реалізація та перевірка зворотного поширення похибки

Мережа: `X → Linear(4, 8) → ReLU → Linear(8, 3)`, дані Iris, крос-ентропія (усереднена за об'єктами), усе у float64.

## Відтворення

```bash
cd lab1
uv sync
uv run python run.py
uv run python run.py --bug
uv run python run.py --extras
```

Код завершується з кодом 0, якщо всі перевірки пройдено (для `--bug` - якщо помилку виявлено).
Готові виводи: `results/correct.md`, `results/correct_extras.md`, `results/bug.md`.
Файли: `data.py` (поділ і стандартизація), `mlp.py` (NumPy-мережа і backprop), `checks.py` (PyTorch-еталон і чисельні похідні), `run.py` (запуск).
Примітка: `torch==2.14.1` на Linux з PyPI тягне CUDA-залежності; для лише CPU це зайве, але на результат не впливає.

## Дані й ініціалізація

- Стратифікований поділ 70/30 через `np.random.default_rng(0)`: класи 0, 1, 2 по черзі, `rng.permutation` індексів класу, перші 35 - train, решта 15 - test (105 / 45).
- Стандартизація: mean і std (`ddof=0`) лише з train, ті самі статистики для test.
- Ініціалізація: новий `default_rng(0)`, спочатку `W1 ~ N(0, 2/4)` (He, std = √(2/4)), потім `W2 ~ N(0, 2/(8+3))` (Xavier, std = √(2/(8+3))), зсуви - нулі.
- Ваги зберігаються як `(in, out)`: `z = a @ W + b`. `torch.nn.Linear` має `(out, in)`, тому при копіюванні в PyTorch матриці транспонуються.

## Прямий прохід і збережені значення

Для батча з N об'єктів (N = 105):

| Крок | Формула | Форма |
|---|---|---|
| вхід | X | (N, 4) |
| передактивація | Z1 = X W1 + b1 | (N, 8) |
| активація | A1 = max(0, Z1) | (N, 8) |
| логіти | Z2 = A1 W2 + b2 | (N, 3) |
| log-softmax | log q = (Z2 − m) − log Σ exp(Z2 − m), m = max по рядку | (N, 3) |
| втрата | L = −(1/N) Σᵢ log q[i, yᵢ] | скаляр |

Стабільність: зсув на максимум робить усі експоненти ≤ 1, а одна з них дорівнює 1, тож сума не обнуляється і `exp` не переповнюється (лекція 1). `--extras` показує: при логітах (1000, 1001, 1002) наївний softmax дає `nan`, стабільна версія - 0.407605964444380, як `torch.cross_entropy` і як при логітах, зсунутих на −1000.

**Що зберігається для backward:** `X`, `Z1`, `A1` і `log q`.
- `X` потрібен для ∇W1, `A1` - для ∇W2 (градієнт ваг шару = δ · (вхід шару)ᵀ, лекція 2);
- `Z1` потрібен лише для маски ReLU `Z1 > 0` (достатньо й булевої маски);
- `log q` дає `q = exp(log q)` для градієнта за логітами. `Z2` окремо не потрібен.
Усе це масиви розміру N × (кількість ознак шару), тому пам'ять активацій зростає лінійно з N.

## Зворотний прохід

Градієнт скалярної втрати - ланцюжок VJP (вектор-рядок × якобіан) справа наліво, повні якобіани не будуються (лекція 1):

1. **Softmax + крос-ентропія** зводяться до `∂L/∂Z2 = (q − Y) / N`, де Y - one-hot. Форма (N, 3). Кожен рядок `q − y` сумується в 0, а компоненти лежать у [−1, 1].
2. `∇W2 = A1ᵀ · dZ2` — (8, N)(N, 3) = **(8, 3)**
3. `∇b2 = Σᵢ dZ2[i, :]` — **(3,)**
4. `dA1 = dZ2 · W2ᵀ` — (N, 3)(3, 8) = (N, 8)
5. `dZ1 = dA1 ⊙ 1[Z1 > 0]` - якобіан поелементної активації діагональний, тож VJP зводиться до маски (у нулі беремо 0, як PyTorch) — (N, 8)
6. `∇W1 = Xᵀ · dZ1` — (4, N)(N, 8) = **(4, 8)**
7. `∇b1 = Σᵢ dZ1[i, :]` — **(8,)**

Розмірності чотирьох градієнтів збігаються з розмірностями параметрів: (4, 8), (8,), (8, 3), (3,).

## Результати звірки з PyTorch

Втрата NumPy `1.456200780114282`, втрата PyTorch `1.456200780114282`.

| Величина | Макс. абс. різниця NumPy / PyTorch | Перевірку пройдено |
|---|---|---|
| Втрата | 2.220e-16 | так |
| Градієнт W1 | 5.551e-17 | так |
| Градієнт b1 | 3.816e-17 | так |
| Градієнт W2 | 1.110e-16 | так |
| Градієнт b2 | 1.527e-16 | так |

Критерій: |a − b| ≤ 1e-12 для кожної пари; усі значення скінченні.

## Чисельна перевірка (центральна різниця, ε = 1e-6)

| Параметр | Градієнт backward() | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---|---|---|---|
| W1[0, 0] | -1.992018433056e-02 | -1.992018439090e-02 | 6.034e-11 | так |
| b1[0] | -7.056611158438e-02 | -7.056611162071e-02 | 3.633e-11 | так |
| W2[0, 0] | 1.352302086055e-01 | 1.352302086977e-01 | 9.218e-11 | так |
| b2[0] | 8.552164484196e-02 | 8.552164498798e-02 | 1.460e-10 | так |

Критерій: |g_num − g_manual| ≤ 1e-7.

**Чому перевірка не порожня.** Контрольні градієнти ненульові (~1e-2…1e-1), тому порівняння 0 з 0 було б безглуздим. Це важливо: при мертвому ReLU градієнт `W1[0, 0]`/`b1[0]` був би нулем, і помилка масштабу на ньому не проявилась би. У нашому запуску мертвих нейронів немає (частки активності 0.45-0.62, `--extras`). Крім того, `--extras` робить чисельну перевірку **всіх 67** елементів параметрів: макс. різниця 2.4e-10.

**Вибір ε** (`--extras`, п. 4): похибка спадає як O(ε²) (усічення) до ε ≈ 1e-4…1e-5, далі зростає як ~u/ε (округлення float64). ε = 1e-6 лежить у розумній зоні; різниця ~1e-10 має чималий запас до порога 1e-7. Для ReLU чисельна похідна ненадійна, лише якщо `Z1` потрапляє в околицю 0 радіусом ε; тут точних нулів у `Z1` немає.

## Дослід із навмисною помилкою

`python run.py --bug` прибирає `dZ2 /= N` у `backward`; `forward` і втрата не змінюються, параметри і 105 об'єктів ті самі, ваги не оновлюються.

**Прогноз (записано до запуску):**
1. Втрата не зміниться, бо змінюється лише backward.
2. `dZ2` стане в N = 105 разів більшим; решта зворотного проходу лінійна за `dZ2`, тому кожен ненульовий елемент усіх чотирьох градієнтів зросте рівно в 105 разів, нулі лишаться нулями.
3. Звірка втрати з PyTorch пройде, звірка градієнтів - ні. Чисельна перевірка впіймає помилку на ненульових градієнтах (на нульовому градієнті помилка була б невидима).

**Результат:**

| Перевірка | Результат |
|---|---|
| Втрата NumPy vs PyTorch | 2.220e-16, пройдено (втрата не змінилась) |
| ∇W1 / ∇b1 / ∇W2 / ∇b2 vs PyTorch | макс. різниці 18.5 / 15.6 / 34.2 / 11.2, **не пройдено** всі |
| Чисельна: W1[0,0], b1[0], W2[0,0], b2[0] | різниці 2.07 / 7.34 / 14.1 / 8.89, **не пройдено** всі |
| Відношення bug / correct | min 104.999999999999, max 105 для всіх 67 ненульових елементів |

Прогноз підтвердився повністю. Висновки:
- Втрата не виявляє цю помилку: вона перевіряє лише forward. Градієнти потрібно перевіряти окремо.
- Інваріанта `Σ db2 = 0` теж не виявляє її (рядки `q − y` сумуються в нуль за будь-якого масштабу). Масштабну помилку ловить лише порівняння з незалежним еталоном (autograd або чисельна похідна).
- Помилка не зламала б програму: навчання з таким градієнтом працювало б як ефективний learning rate, збільшений у N разів, і могло б розбігатися або виглядати як «погані гіперпараметри» (лекція 1, розділ про приховані помилки).
Після досліду правильна реалізація відновлена: `buggy=False` за замовчуванням.
